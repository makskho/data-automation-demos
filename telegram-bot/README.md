# Telegram-бот: меню FAQ и заявки клиентов

Рабочий пример бота для малого бизнеса. Клиент листает меню вопросов и ответов или оставляет заявку; заявка сохраняется в базе и сразу приходит администратору в Telegram, а все заявки можно выгрузить одной командой в Excel.

Автор: Максим. Тексты и данные в примере вымышленные.

## Что умеет бот

- **Меню FAQ.** `/start` открывает кнопки с разделами. Вложенность любая, на каждом экране есть «Назад» и «В меню». Всё дерево лежит в файле `faq.yaml`, править его может не программист.
- **Заявка.** Кнопка «Оставить заявку» запускает диалог из трёх шагов: имя, телефон, описание задачи. Ответы проверяются, при ошибке бот объясняет, что не так, и остаётся на том же шаге. `/cancel` отменяет форму.
- **Проверка телефона.** Принимает `+7 999 123-45-67`, `8 (999) 123-45-67`, `9991234567` и международные номера, приводит к виду `+79991234567`.
- **Хранение и уведомление.** Заявка пишется в SQLite (`leads.db`), администратору уходит сообщение с именем, телефоном, задачей и ссылкой на автора. Если уведомление не дошло, заявка в базе всё равно есть.
- **Защита от флуда.** Один человек может отправить одну заявку за N минут (по умолчанию 10). Проверка выполняется и при открытии формы, и при отправке.
- **Выгрузка.** `/export` у администратора присылает файл `leads.xlsx` со всеми заявками (шапка, фильтр, закреплённая строка). Остальным команда не отвечает данными.

## Запуск в три команды

Нужен Python 3.10 или новее. Токен бота выдаёт @BotFather, ID чата для заявок узнаёт @userinfobot.

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt     # Linux/macOS: .venv/bin/pip
cp .env.example .env                                                       # впишите BOT_TOKEN и ADMIN_CHAT_ID
.venv/Scripts/python -m bot                                                # Linux/macOS: .venv/bin/python -m bot
```

Файл `.env`:

| Переменная | Что это | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен от @BotFather | обязательно |
| `ADMIN_CHAT_ID` | числовой ID чата, куда приходят заявки; команду `/export` тоже принимает только он | обязательно |
| `DB_PATH` | файл базы SQLite | `leads.db` |
| `FAQ_PATH` | файл с деревом FAQ (`.yaml` или `.json`) | `faq.yaml` |
| `FLOOD_MINUTES` | пауза между заявками одного человека, `0` выключает защиту | `10` |

Чтобы заявки приходили в группу, добавьте бота в группу и впишите её ID (он отрицательный). Если в `.env` ошибка, бот не запускается и пишет, что исправить.

## Как править FAQ

Откройте `faq.yaml` в любом текстовом редакторе. Каждая кнопка — блок из четырёх полей:

```yaml
items:
  - id: prices                 # уникальный код: a-z, 0-9, _ и -
    title: "💰 Цены и сроки"   # надпись на кнопке
    text: |                    # ответ, который увидит клиент
      Лендинг - от 15 000 руб., 5-7 дней.
    children: []               # вложенные кнопки (необязательно, любая глубина)
```

- Чтобы добавить пункт, скопируйте соседний блок и поменяйте `id`, `title`, `text`.
- Чтобы сделать подменю, добавьте внутрь `children:` такие же блоки. У кнопки с подменю `text` можно не писать, у конечной он обязателен.
- После правки перезапустите бота. Ошибки файла (повторный `id`, пустой текст, слишком длинная надпись) бот показывает при запуске с указанием места, например `items[1].children[0]: id 'a' повторяется`.
- Тот же формат принимается в JSON: укажите `FAQ_PATH=faq.json`.

## Тесты

```bash
.venv/Scripts/pip install -r requirements-dev.txt
.venv/Scripts/python -m pytest -q
```

84 теста, сеть не нужна: Telegram подменён заглушкой, диалоги проходят через настоящий диспетчер бота.

- загрузка и проверка дерева FAQ: 11 видов ошибок, дубликаты id на разных уровнях, JSON, длина `callback_data`, кнопки «Назад»;
- телефон и имя: форматы `+7`, `8`, `9…`, международные, неверные номера;
- диалог целиком: заявка сохраняется и уходит администратору, ошибки не сбивают шаг, `/cancel` и `/start` сбрасывают форму, ответ не текстом отклоняется;
- антифлуд: блокировка, разрешение после паузы, раздельно по людям, повторная проверка при отправке;
- сбой уведомления администратору не теряет заявку;
- `/export`: файл приходит администратору и не приходит остальным; содержимое .xlsx сверено по ячейкам; текст вида `=HYPERLINK(...)` остаётся текстом, а не формулой;
- база: данные переживают перезапуск, SQL-инъекция в имени сохраняется как обычная строка.

## Ограничения

Бот работает через long polling на одном процессе, состояние диалога хранится в памяти: после перезапуска незаконченная форма сбрасывается (сохранённые заявки не теряются). Для нескольких серверов или webhook нужно заменить хранилище состояний и вынести SQLite в серверную базу. Выгрузка делает полный список без фильтров по датам.

## English summary

A runnable sample bot built with Python 3 and aiogram 3: an inline-keyboard FAQ menu loaded from an editable `faq.yaml` (nested sections, back button), a three-step lead form (name, phone, task) with validation and an anti-flood limit (one lead per user per N minutes), SQLite storage, an instant notification to an admin chat, and an admin-only `/export` command that returns all leads as an `.xlsx` file.

Run: `python -m venv .venv`, install `requirements.txt`, copy `.env.example` to `.env` (set `BOT_TOKEN` and `ADMIN_CHAT_ID`), then `python -m bot`. Tests: `pip install -r requirements-dev.txt && python -m pytest -q` (84 tests, no network; Bot API is replaced by a fake session, handlers run through the real dispatcher). Limits: long polling, in-memory conversation state, single-process SQLite. Data and texts in the sample are fictional.
